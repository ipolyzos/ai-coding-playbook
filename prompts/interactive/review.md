# Review a code change

## Inputs
- Diff or PR: [reference]
- Intended behavior: [requirements]
- Relevant conventions: [standards]

## Workflow
1. Inspect the diff and surrounding code, not just the summary.
2. Look for correctness, compatibility, concurrency, security, performance, and test gaps.
3. Report actionable findings ordered by severity with precise file and line references.
4. Distinguish verified defects from hypotheses and stylistic preferences.
5. Summarize remaining risk and checks that were not run.

Avoid unsupported claims of approval or production readiness.
