# Contributing

1. Branch from the latest `main` using `feat/`, `fix/`, or `docs/`.
2. Keep each PR focused on one coherent capability.
3. Update the prompt catalog and include realistic examples when adding templates.
4. Validate JSON contracts and Markdown links; report exact commands and outcomes.
5. Open a PR describing motivation, scope, tests, and limitations. Address review and CI feedback before merge.

Never merge a failing PR or misrepresent validation results.
